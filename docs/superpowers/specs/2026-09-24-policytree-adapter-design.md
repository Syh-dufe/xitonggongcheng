# policytree 因果策略树适配设计

## 目标

在不改变既有半合成呼叫中心仿真器、事实日志和反事实评价隔离规则的前提下，为因果规范性 AI 提供可复现的公开实现接口。实现依据为 Athey 与 Wager（2021）的观察性数据策略学习框架、Zhou、Athey 与 Wager（2023）的多行动离线策略学习，以及开源的 `grf` 与 `policytree` R 包。

## 边界

本阶段只建立数据适配、训练、策略导出和最小运行验证，不改变仿真机制，也不把 Oracle 或潜在结果用于训练。训练输入只能是事实 `observed_log.csv`；Oracle 仅保留给既有的独立仿真评价环节。

## 可选实现路径

1. **R 原生实现（采用）**：Python 工程导出无泄漏训练/测试数据，R 脚本用 `grf` 估计多行动结果与倾向成分、用 `policytree` 学习固定深度树。优点是最贴近见刊方法和官方开源实现；代价是需安装 R 包。
2. **Python 重写双重稳健策略树**：运行环境单一，但需要自行复刻核心算法，无法主张直接复用成熟实现。
3. **只导出数据、人工运行 R**：风险最低，但无法形成一键可复现实验接口。

选择路径 1。Python 仍是仿真和评估主工程；R 仅承担已公开的因果策略学习步骤。

## 共同实验接口

每条样本是一段 30 分钟的决策单元，且按 `episode_id`（日期）切分，不允许随机逐行切分。

- 状态 `X`：`period`、三类当前队列、优先队列、最长等待期、需求状态；不包含行动后结果和隐藏管理者告警。
- 行动 `A`：事实日志中的 `action`，取值 0、1、2、3。
- 成本 `Y`：`total_cost + gamma * next_queue`；`gamma` 写入运行配置，默认值需显式记录。
- 约束：所有策略使用同一批状态变量、四档行动、相同训练日期、相同测试日期和相同树深度。

## 三种策略

1. **历史模仿树**：用相同深度的分类树拟合 `A ~ X`，表示直接复制历史行动规律。
2. **关联型规范性树**：对每个行动拟合 `E[Y | X, A=a]`，给每个样本选择预测成本最低的行动，再用相同深度的树压缩为可执行处方。
3. **因果规范性树**：用 `grf` 的多行动因果森林与双重稳健得分构造四行动成本分数，用 `policytree` 在相同深度限制下最小化成本。

策略 3 是本阶段适配目标；策略 1 与 2 的接口同时预留，确保后续比较只改变学习方式。

## 产物与防泄漏

- Python 命令导出 `policy_training.csv`、`policy_test.csv`、`policy_manifest.json`；其中只保留 `episode_id`、`split`、`X`、`A`、`Y`。
- `policy_manifest.json` 记录源日志哈希、特征列、成本定义、训练/测试日期数、行动支持度和是否使用反事实（必须为 `false`）。
- R 训练脚本输出模型、每个测试样本的行动建议和策略树文本；不读取 `oracle_counterfactuals.csv`。
- Python 读取策略建议后，借助既有同随机种子仿真器做独立策略评价。

## 失败处理与诊断

训练前验证：行动必须为四档、训练/测试日期不交叠、每档行动有样本、没有 Oracle/潜在结果列、特征无缺失。若 R、`grf` 或 `policytree` 未安装，命令应给出明确安装提示而非静默回退为其他算法。输出各行动样本量及估计倾向概率分位数，作为重叠性诊断。

## 测试

以小型事实日志开展测试驱动开发，验证：导出列白名单；按日期切分且无泄漏；成本构造正确；行动支持度不足时失败；清单明确声明未使用反事实。R 可用时再增加一个集成测试，确认输出四档合法行动及固定深度的策略树。
