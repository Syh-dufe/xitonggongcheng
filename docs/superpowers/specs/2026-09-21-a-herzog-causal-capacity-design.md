# 基于 A-Herzog 的动态因果服务产能配置环境：设计规格

## 1. 目标与研究定位

本项目将以 A-Herzog `Callcenter-Simulator` 6.2.235（提交 `2119d92`）作为事件驱动呼叫中心仿真内核，使用 Technion 匿名银行呼叫日志校准可识别的运营参数，并在外部增加历史产能决策、观测日志生成、因果政策学习和样本外政策评价模块。

研究比较两类规范性 AI：

1. 从带偏历史行动及结果中直接学习规律、但不显式校正行动选择机制的方法；
2. 显式估计行动倾向或条件处理效应、校正可观测历史选择偏差的因果规范性方法。

仿真器本身不作为论文创新主张。论文的贡献定位为：在公开且可引用的多技能呼叫中心仿真内核上，构建由真实运营日志校准、包含历史决策偏差和动态积压的因果规范性产能配置实验框架。

## 2. 上游软件与可追溯性

- 上游项目：`A-Herzog/Callcenter-Simulator`
- 固定版本：`6.2.235`
- 固定提交：`2119d92`
- 许可证：Apache License 2.0
- 项目 DOI：`10.5281/zenodo.12792568`
- 运行要求：Java 11 或更高版本

实现不得依赖浮动的 `latest` 版本。仓库必须记录上游版本、提交、下载地址、文件哈希、许可证、NOTICE、补丁清单和构建环境。任何修改后的二进制或源码分发均保留 Apache 2.0 要求的版权与许可声明，并明确标识本文修改。

## 3. 可信性边界

### 3.1 保留的 A-Herzog 原生机制

以下运行机制原则上不重写：

- 离散事件调度；
- 客户到达、排队和离开；
- 多客户类型和多技能坐席组；
- 技能匹配、优先级和转接；
- 服务、后处理、客户耐心、放弃和重拨；
- 坐席上下班、可用性和利用率；
- 基础运行统计。

原项目的可信性只能覆盖这些未被实质改变的机制。本文新增接口、参数映射、行为策略和因果评价必须独立验证。

### 3.2 本文新增机制

- Technion 日志到 A-Herzog 参数的转换；
- 每 30 分钟一次的外部决策钩子；
- 状态输出和四级产能行动接口；
- 可复现的随机种子与随机流管理；
- 历史管理者行为策略和观测日志；
- 历史规律型与因果规范性 AI；
- 样本外配对政策评价、成本和安全约束；
- 运行清单、防泄漏检查和复现实验脚本。

## 4. 数据边界与参数映射

### 4.1 真实日志负责的参数

Technion 日志只用于估计能够从记录中识别的变量：

| 原始信息 | A-Herzog 参数 | 转换规则 |
|---|---|---|
| 日期、星期、进入时间 | 分时段到达过程 | 按星期、30 分钟、业务类别估计 |
| `PS/PE/NW` | `regular` 客户类型 | 合并为普通业务 |
| `IN/NE` | `specialist` 客户类型 | 合并为专业业务 |
| `TT` | `callback_special` 客户类型 | 映射为回拨或特殊业务 |
| 服务开始、结束和结果 | 服务时间分布 | 仅使用有效完成人工服务的通话 |
| 排队时间和 `HANG` | 耐心时间分布 | 放弃通话为事件，已服务通话按右删失处理 |
| 优先级 | 客户优先级 | 按业务类别估计优先客户比例 |
| 日内需求变化 | 正常、高峰、严重高峰场景 | 由校准期需求分位数识别 |

参数估计只使用按日期划分的训练期；留出日期仅用于验证。原始客户和坐席标识不进入分析产物或版本库。

### 4.2 继续半合成的变量

原始日志不能可靠识别以下变量，因此必须显式标记为半合成：

- 普通和专业坐席的基准数量；
- 应急或临时增援来源；
- 历史管理者采用的产能行动；
- 行动倾向和决策噪声；
- 人员、等待、放弃和安全违反成本；
- 未被采用行动的潜在结果。

基准人员配置和成本只用于相对政策比较，并通过多组敏感性场景检验，不能解释为该银行的真实排班或真实货币成本。

## 5. 业务与行动模型

### 5.1 资源结构

- 普通坐席组主要服务 `regular`；
- 专业坐席组优先服务 `specialist` 和 `callback_special`；
- 专业坐席空闲时可以支援 `regular`；
- 应急坐席组只在增援行动生效时启用；
- 跨技能服务通过客户类型与技能等级对应的服务时间倍率体现效率损失。

不由数据支持的重拨、转接和回访机制在基准实验中关闭，在有明确参数依据后才进入扩展场景。

### 5.2 决策频率和行动

一个 episode 代表一个营业日。A-Herzog 每运行 30 分钟触发一次决策边界，暂停并输出状态。外部策略返回一个离散行动：

- `a0`：0% 增援；
- `a1`：10% 增援；
- `a2`：20% 增援；
- `a3`：30% 增援。

行动在下一 30 分钟生效。增援人数以基准可用坐席为基础按预先固定的普通/专业比例取整；取整规则在配置中唯一确定，不能由不同策略自行选择。

## 6. Java 仿真内核的最小扩展

### 6.1 决策钩子

在每个 30 分钟边界增加一个可测试的决策事件：

1. 完成边界时刻之前的所有事件；
2. 汇总当前可观测状态；
3. 通过桥接接口输出状态；
4. 等待一个合法行动；
5. 调整下一时段可用坐席；
6. 恢复事件运行。

同一时间戳的事件处理顺序必须固定并记录，避免边界到达事件在不同策略下产生不一致定义。

### 6.2 状态协议

状态采用带版本号的 JSON Lines 协议，至少包含：

- `schema_version`、`episode_id`、`period`、`seed`；
- 星期、30 分钟时段和需求预测；
- 各业务到达量、队列量、平均和最大等待；
- 各坐席组在岗数、空闲数和利用率；
- 上一期行动和累计增援量；
- 截至当前的服务量、放弃量和安全指标。

协议只暴露决策时刻真实可见的信息，不输出未来到达、未来服务实现或测试场景标签。

### 6.3 行动协议

Python 返回包含 `episode_id`、`period` 和 `action` 的 JSON 行。Java 端拒绝缺失、越界、重复或时段不匹配的行动。通信超时、进程异常或非法行动使当前 episode 失败并写入错误清单，不静默回退到默认行动。

### 6.4 随机性

分别为到达、服务、耐心和坐席可用性建立确定性随机子流。训练、验证和测试种子集合完全分离。比较策略时，在同一个测试 episode 上共享相同外生子流，但不共享由行动内生造成的队列状态。

若上游内核未公开足够的随机种子入口，只增加种子注入和子流派生接口，不替换原随机分布或事件实现。

### 6.5 无界面运行

实验只使用 headless 运行。Python 启动 Java 子进程，通过标准输入和标准输出交换 JSON Lines；诊断日志写入标准错误，禁止混入协议输出。桥接器负责超时、退出码、协议版本和结果文件校验。

## 7. Python 端职责

Python 不重新实现 A-Herzog 的排队过程，仅承担：

- 真实数据读取、脱敏、训练/留出划分和参数校准；
- A-Herzog 模型文件或启动配置生成；
- Java 进程生命周期和 JSON Lines 协议；
- 历史管理者行为策略；
- 规范性 AI 训练和行动选择；
- 成本、安全约束、样本外评价和统计检验；
- 配置、哈希、种子、版本和运行环境记录。

现有 Python 仿真器在迁移阶段保留为回归参考和跨仿真器稳健性工具，不立即删除或覆盖。只有新后端完成验证并产生等价输出后，才将其设为默认主实验环境。

## 8. 历史日志与因果实验

### 8.1 历史行为策略

历史管理者根据可观测状态以非随机方式选择增援行动。风险得分包含时段、需求预测、各类积压、等待、坐席利用率、优先客户比例和上一期行动；softmax 温度控制行动重叠，偏差强度控制高风险状态下增援倾向。

主实验满足条件可交换性：影响行动与结果的主要混杂变量均写入观测日志。未观测管理者警报只在单独的敏感性实验中启用，不能把普通因果校正在隐藏混杂下解释为无偏识别。

### 8.2 事实日志

每个决策时点只记录：

```text
可观测状态 X_t、实际行动 A_t、实现结果 Y_t、下一状态 X_{t+1}
```

训练数据不得包含未采用行动的结果、未来随机量、Oracle 行动或测试集统计。

### 8.3 比较方法

确认性比较至少包括：

- 历史行为策略；
- 固定 0%、10%、20%、30% 增援策略；
- 直接模仿历史行动的方法；
- 未经倾向校正的结果预测后优化方法；
- 倾向加权或双重稳健的因果规范性方法；
- 因果森林加策略树或其他可解释多行动政策学习方法。

深度学习和强化学习不属于基准实现的必要条件。

### 8.4 样本外评价

所有学习方法仅使用历史行为策略生成的训练日志。训练完成后，将每个策略分别接入 A-Herzog，在完全独立的测试 episode 上运行。相同测试 episode 的策略共享外生随机种子，以配对方式比较全日累计结果。

主要指标为：

- 总成本和相对历史策略的成本改善；
- 平均等待时间和 P90 等待时间；
- 放弃率和服务水平；
- 期末积压；
- 坐席利用率和累计增援量；
- 安全约束违反率；
- 多随机种子的均值、置信区间和最差分位表现。

Oracle 只作为小规模场景的上限参考，不是主评价所必需。若运行状态无法可靠复制，不为生成逐行潜在结果而大幅侵入上游事件内核。

## 9. 输出与复现

一次运行至少产生：

- `observed_log.csv`：历史事实日志；
- `episode_summary.csv`：按日汇总；
- `policy_metrics.csv`：策略配对评价；
- `simulation_validation.csv`：真实留出数据与模拟结果比较；
- `bridge_events.jsonl`：Java/Python决策交互记录；
- `run_manifest.json`：上游版本、补丁哈希、配置、种子、数据哈希和运行环境；
- `error_manifest.json`：失败 episode、协议错误和重试情况。

原始 Technion 文件、客户标识和坐席标识不得进入提交、日志或共享产物。

## 10. 验证标准

### 10.1 上游与构建验证

- 固定版本能够在干净的 Java 11+ 环境构建；
- 上游自带测试在扩展前后均通过；
- 许可证、NOTICE、版本和补丁清单完整；
- headless 运行不依赖图形界面或人工点击。

### 10.2 接口验证

- 48 个决策期严格按顺序发生；
- Python 动作与 Java 实际启用的坐席数一致；
- 非法、重复和错时段动作被拒绝；
- 固定配置和种子产生完全相同的协议和结果；
- 标准输出只包含协议数据，诊断信息不会破坏解析。

### 10.3 仿真机制验证

- 各类客户满足流量守恒；
- 所有队列和计数非负；
- 无兼容技能坐席时客户不能被错误服务；
- 零坐席时不能完成服务；
- 在共同随机数和受控简化场景下，提高产能不会系统性增加容量导致的等待与放弃；
- 简化单类场景与 Erlang A 或可验证解析结果在预设容差内一致。

### 10.4 数据和因果验证

- 留出日期的到达曲线、服务分布、等待分布和放弃率得到报告；
- 训练日志不包含未来变量和反事实结果；
- 主实验具有足够行动重叠，极端倾向概率单独报告；
- 训练、调参和测试种子无交叉；
- 隐藏混杂只作为敏感性场景并明确降低因果识别结论强度。

## 11. 风险与降级策略

1. **上游缺少可复用的逐时段接口**：在独立包内增加决策事件和桥接类，不重写事件引擎。
2. **状态复制成本过高**：主评价采用独立测试 episode 的在线策略部署，不强制生成逐行 Oracle。
3. **Java/Python通信成为性能瓶颈**：保持单个 Java 进程运行完整 episode，每 30 分钟只交换一行状态和一行行动。
4. **人员配置无法由日志识别**：使用预先声明的半合成基准和敏感性网格，不把结果解释为真实排班恢复。
5. **上游改动过大削弱可信性**：记录变更范围；一旦触及排队、路由或放弃核心，必须增加与未修改版本的对照验证。

## 12. 论文表述边界

允许的表述：

> 本文基于 A-Herzog 公开发布的事件驱动呼叫中心仿真平台扩展实验环境，保留其多业务、多技能坐席、时变到达、客户放弃及技能路由机制；使用 Technion 真实运营日志校准需求、服务与耐心参数，并增加历史产能决策、选择偏差和样本外因果政策评价模块。

不允许的表述包括：

- 全部环境或全部参数均来自真实企业；
- 半合成人员行动是真实排班；
- 使用开源仿真器本身构成论文创新；
- A-Herzog 原项目已经验证本文新增的因果机制；
- 在未观测混杂场景中仍然识别了无偏因果效应。

## 13. 实施完成条件

- A-Herzog 固定版本可在本项目中自动构建或取得可验证二进制；
- Technion 校准参数可生成可运行的 A-Herzog 场景；
- 30 分钟状态—行动协议完成端到端运行；
- 历史事实日志、至少两类规范性 AI 和固定策略可在独立测试 episode 上评价；
- 所有验证测试和原有 Python 回归测试通过；
- 复现实验只需文档中列出的公开依赖、数据准备步骤和命令；
- 论文能够逐项区分上游机制、真实数据校准、半合成假设和本文新增贡献。
